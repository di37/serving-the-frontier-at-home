The warmup derived from the geometry, not from habit. The DFlash2 attention path's block size is `BLOCK = min(256, next_pow2(s + 8))`, where 8 = 1 + *k* is the queries per request at *k*=7; working backwards, BLOCK 8 is unreachable because the minimum *s*=1 already rounds 9 up to 16, so the live values are exactly {16, 32, 64, 128, 256} and the prompt lengths *s* ∈ {1, 24, 56, 120, 248} hit each once. Every rung is checked against the server's own `/tokenize`, because a one-token-off prompt silently warms the wrong shape. Crossing that ladder is a second dimension no reasonable warmup would think to cover: the Hub's `generation_config.json` stamps `top_p=0.95` onto every request that does not override it, so three engineered arms are needed to reach all three Triton kernels — and the script proves it by grepping the compiled `.ttir` for whether the `%K` and `%P` SSA values are actually used.
