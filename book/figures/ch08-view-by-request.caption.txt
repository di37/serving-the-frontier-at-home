Patches 2 and 2b. `prepare_context` reshaped the flat target hidden states into a rectangular `[batch, seq, H]` view asserting equal rows per request, but chunked prefill mixes a prefilling request beside a decoding one in the same step — `got 41 rows for batch_size=2`. Patch 2 added a ragged path keyed on `query_start_loc` but computed raggedness only inside the branch where a rejection tensor existed, so three fresh requests prefilling together with nothing to reject still fell through to the rectangular view — `got 166 rows for batch_size=3`. Patch 2b decoupled the two: ragged detection runs whenever GPU-mask mode is on, with `rejected` defaulting to zeros. Found by a GSM8K quality eval, not a benchmark.
